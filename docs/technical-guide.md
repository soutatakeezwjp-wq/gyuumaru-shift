# ぎゅう丸シフト管理システム 技術説明書

このドキュメントでは、ぎゅう丸シフト管理システムの技術的な構成を、
全体像から細かい部分まで丁寧に説明します。


---


## 1. システムの全体像

ぎゅう丸シフト管理システムは、焼肉チェーン「ぎゅう丸」の全13店舗のシフト管理を
ひとつのWebアプリで行うために作られたシステムです。

スマホのブラウザからアクセスするだけで使えるWebアプリで、
専用アプリのインストールは不要です。

このシステムには2つのバージョンがあります。

| 項目 | GAS版（旧バージョン） | Cloudflare版（現在のメインシステム） |
|------|----------------------|--------------------------------------|
| 動いている場所 | Googleのサーバー | Cloudflareのサーバー（世界中に分散） |
| データの保存先 | Googleスプレッドシート | Cloudflare D1（SQLiteデータベース） |
| プログラミング言語 | Google Apps Script（JavaScript） | TypeScript |
| 画面表示の速度 | 3〜5秒かかる | 1秒以内 |
| 見た目 | 「Google Apps Scriptで作成」のバナーが出る | バナーなし、見た目がきれい |
| 費用 | 無料 | 無料（Freeプランの範囲内） |

現在はCloudflare版がメインで使われています。
以下、Cloudflare版を中心に説明します。

## 2. 使っている技術・ツール

### 2-1. サーバー側（バックエンド）

- Cloudflare Workers
  サーバーレスという仕組みで動いています。
  自分でサーバーを用意する必要がなく、Cloudflareが世界中に持っている
  サーバーの中で自動的にプログラムが動きます。
  日本からアクセスすると、日本に近いサーバーが応答するので速いです。

- Hono（ホノ）
  Webアプリケーションを作るためのフレームワーク（土台）です。
  日本人が作った軽量で速いフレームワークで、
  Cloudflare Workersと相性がとても良いです。バージョンは4.7.0。

- Cloudflare D1
  データベースです。SQLiteというデータベースをCloudflareの上で動かせます。
  スタッフの情報、シフト希望、確定シフト、人件費などのデータはすべてここに保存されます。

- TypeScript
  JavaScriptをより安全にした言語です。バージョンは5.8.0。
  「この変数は文字列しか入れられない」「この関数は数値を返す」といった
  型のチェックを自動でやってくれるので、プログラムの間違いを事前に防げます。

- Wrangler
  Cloudflare Workers用の開発ツールです。バージョンは4.10.0。
  ローカルでの開発テストや、本番環境へのデプロイ（公開）に使います。

### 2-2. 画面側（フロントエンド）

- HTML / CSS / JavaScript（Vanilla JS）
  ReactやVueなどのフレームワークは使わず、シンプルな構成になっています。
  これにより、読み込み速度が速く、複雑な設定も不要です。

- シングルページアプリケーション（SPA）
  1つのHTMLファイルの中にすべての画面が入っています。
  画面を切り替えるときにページ全体を読み直さず、
  JavaScriptで表示/非表示を切り替えるので、操作がなめらかです。

### 2-3. 外部サービスとの連携

- LINE Messaging API
  シフトが確定したときや、希望の提出締切が近いときに、
  LINEのグループに自動で通知を送ります。

### 2-4. 開発に使うツール

- npm（Node.jsのパッケージ管理）
- Git / GitHub（ソースコードのバージョン管理と共有）
- clasp（GAS版をローカルから操作するためのツール）


すべてのテーブルに store_id というカラムがあります。

1つのデータベースで13店舗すべてのデータを安全に分けて管理できます。

## 6. 認証の仕組み（JWT）

JWTとは JSON Web Token の略で、「この人は誰で、何ができるか」を
安全に証明するための仕組みです。

### 6-1. ログインの流れ

スタッフの場合:
1. 店舗を選ぶ
2. 自分の名前を選ぶ
3. サーバーがJWTトークンを発行する
4. ブラウザがそのトークンを保存する

管理者の場合:
1. 店舗を選ぶ
2. パスワードを入力する
3. サーバーがパスワードをSHA-256で暗号化して、保存されているものと比較する
4. 一致したら、JWTトークンを発行する
5. ブラウザがそのトークンを保存する

パスワードが未設定の場合（初回ログイン時）:
入力したパスワードがそのまま新しいパスワードとして登録されます。

### 6-2. JWTトークンの中身

```
{
  storeId: 1,          ... どの店舗か
  role: "admin",       ... 管理者かスタッフか（"admin" または "staff"）
  staffId: "STF_xxx",  ... スタッフの場合、そのID
  exp: 1743292800      ... トークンの有効期限（24時間後）
}
```

### 6-3. トークンの使い方

ログイン後のすべてのAPI呼び出しには、
リクエストのヘッダー（補足情報）にトークンを含めます。

```
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9.eyJzdG9yZUlkIjox...
```

サーバーはこのトークンを毎回チェックして、
- トークンが改ざんされていないか（署名の検証）
- 有効期限が切れていないか
- リクエストしたデータにアクセスする権限があるか
を確認します。

### 6-4. 署名のアルゴリズム

HS256（HMAC-SHA256）を使っています。
サーバーだけが知っている秘密の鍵（JWT_SECRET）で署名するので、
トークンを勝手に作ったり改ざんしたりすることはできません。

暗号化にはWeb Crypto APIを使っています。
これはブラウザやCloudflare Workersに組み込まれている標準の暗号化機能です。

## 7. シフト自動作成アルゴリズム

シフト表の自動作成は、このシステムの中で最も複雑なロジックです。
4つのステップで動きます。

### ステップ1: 出勤希望者の仮配置

まず、全スタッフのシフト希望をデータベースから取得します。
「出勤希望」を出しているスタッフを、その日のシフトに仮配置します。

- 出勤希望に開始時間・終了時間が指定されていればそれを使う
- 指定がなければ、営業開始時間〜営業終了時間（例: 11:00〜22:00）をセット

### ステップ2: 人数チェック

各日付について、ポジション別の配置人数を数えます。

| 条件 | ホール最低人数 | キッチン最低人数 |
|------|---------------|-----------------|
| 平日（月〜金） | 3人 | 2人 |
| 土日・祝日 | 5人 | 4人 |

足りない日があれば「不足リスト」に記録します。
例: 「4月15日（土）のホールが3人足りない」

### ステップ3: 不足分の補充

不足している日・ポジションについて、追加で入れられる人を探します。

候補になれるスタッフの条件:
1. そのポジション（ホール/キッチン）の人であること
2. その日にまだシフトが入っていないこと
3. その日に「休み希望」を出していないこと
4. 以下の制約をすべてクリアすること

制約チェック（3つのルール）:
- 連勤チェック: 6日連続で働いていたら、7日目は入れない
- インターバルチェック: 前日のシフト終了から11時間未満しか空いていなければ入れない
- 週上限チェック: その週の労働時間が40時間を超えそうなら入れない

候補者の優先順位:
1. 「どちらでも」と回答した人（優先的にシフトに入ってもらう）
2. 何も回答していない人

この優先順位で必要な人数分だけ追加配置します。

### ステップ4: 保存と警告

完成したシフト表をデータベースに保存します。
ステップ3で人数が足りなかった日があれば、警告メッセージを返します。

例: 「4/15(土) 土日 ホール: 必要5人に対して4人しか確保できません」

管理者はこの警告を見て、手動で調整できます。

## 8. 人件費計算のロジック

### 8-1. 労働時間の計算

各シフトの実働時間は以下のように計算します。

```
実働時間 = 勤務終了時間 - 勤務開始時間 - 休憩時間
```

休憩時間は労働基準法に基づく自動計算:
- 6時間以下: 休憩なし
- 6時間超〜8時間以下: 45分の休憩
- 8時間超: 60分の休憩

日をまたぐシフト（例: 18:00〜翌2:00）にも対応しています。

### 8-2. 基本給の計算

雇用区分によって計算方法が違います。

- 正社員: 月給がそのまま基本給
  例: 月給250,000円 → 基本給250,000円

- アルバイト・パート: 時給 x 実働時間
  例: 時給1,000円 x 月120.5時間 → 基本給120,500円

### 8-3. 深夜手当の計算

22:00〜翌5:00の時間帯に働いた場合、追加で手当が付きます。
ただし、アルバイト・パートのみが対象です（正社員は月給に含まれる扱い）。

```
深夜手当 = 時給 x 深夜に働いた時間 x 0.25
```

例: 時給1,000円で22:00〜24:00の2時間深夜に働いた場合
→ 1,000 x 2 x 0.25 = 500円

### 8-4. 残業手当の計算

正社員とアルバイト・パートで計算方法が違います。

正社員の場合:
月60時間を超えた分に対して1.3倍の割増

```
時間あたり換算 = 月給 / 160時間（基準労働時間）
残業手当 = 時間あたり換算 x 超過時間 x 1.3
```

例: 月給250,000円で月70時間働いた場合
→ (250,000 / 160) x (70 - 60) x 1.3 = 1,562.5 x 10 x 1.3 = 20,312円

月80時間を超えると「危険ライン」として警告が表示されます。

アルバイト・パートの場合:
週40時間を超えた分に対して0.25倍の割増

```
残業手当 = 時給 x 週の超過時間 x 0.25
```

例: 時給1,000円で1週間に45時間働いた場合
→ 1,000 x (45 - 40) x 0.25 = 1,250円

### 8-5. 交通費

```
交通費合計 = 1日あたりの交通費 x 出勤日数
```

### 8-6. 合計人件費

```
合計 = 基本給 + 深夜手当 + 残業手当 + 交通費合計
```

## 11. セキュリティ対策

### 11-1. パスワードの暗号化

管理者パスワードはSHA-256でハッシュ化（一方向の暗号化）して保存しています。
元のパスワードに戻すことはできません。
ログイン時は、入力されたパスワードも同じ方法でハッシュ化して、
保存されているハッシュ値と一致するかを比較します。

### 11-2. SQLインジェクション対策

データベースへのクエリはすべてPreparedStatement（プレースホルダー）を使っています。
ユーザーが入力した値をそのままSQL文に埋め込まないので、
悪意のあるSQL文を注入される攻撃を防いでいます。

### 11-3. CORS設定

CORSとは、異なるドメインからのアクセスを制御する仕組みです。
Honoのcorsミドルウェアで設定しています。

### 11-4. 機密情報の管理

以下の情報は .gitignore でGitHubにアップロードされないようにしています。
- wrangler.toml（JWTシークレット、D1のデータベースIDを含む）
- .clasp.json（GASプロジェクトIDを含む）
- node_modules/（外部ライブラリ）

代わりに wrangler.toml.example という安全な見本ファイルを用意しています。

### 11-5. マルチテナント分離

すべてのデータベースクエリに WHERE store_id = ? の条件が付いています。
A店舗のスタッフがB店舗のデータにアクセスすることはできません。

## 12. 開発・デプロイの手順


## 13. GAS版との違い（技術的な比較）

### 13-1. データの保存先

GAS版: Googleスプレッドシート
- メリット: 管理者がスプレッドシートを直接開いてデータを確認・修正できる
- デメリット: 読み書きが遅い。大量のデータになると動作がさらに遅くなる

Cloudflare版: D1（SQLite）
- メリット: 読み書きが超高速（1〜18ミリ秒）。インデックスで検索も速い
- デメリット: データを直接見るにはAPIやコマンドを使う必要がある

### 13-2. APIの呼び出し方

GAS版:
```javascript
google.script.run.withSuccessHandler(callback).functionName(params)
```
GAS独自の方式。コールバック関数で結果を受け取る。

Cloudflare版:
```javascript
fetch('/api/endpoint', { method: 'GET', headers: { Authorization: 'Bearer xxx' } })
```
標準的なREST API方式。どんなクライアント（Webブラウザ、スマホアプリ等）からでも使える。

### 13-3. 認証の方式

GAS版: GASのプロパティサービスでパスワードを管理
Cloudflare版: JWT（JSON Web Token）でトークンベースの認証

### 13-4. HTMLのテンプレート

GAS版: GASのテンプレートエンジンで複数のHTMLファイルを結合
Cloudflare版: 1つのindex.htmlに全画面を格納し、CSSのdisplayで切り替え
