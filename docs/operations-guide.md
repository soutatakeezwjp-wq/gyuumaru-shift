# ぎゅう丸シフト管理システム 運用・使い方ガイド

このガイドでは、ぎゅう丸シフト管理システムの日々の使い方を、
スタッフ向け・管理者（店長）向けにそれぞれ説明します。
スマホからの操作を基本にしています。


---


## 1. はじめに

### 1-1. このシステムでできること

- スタッフがスマホからシフト希望を出せる
- 店長がシフト表を自動で作れる（手動での調整もできる）
- 確定したシフトをLINEで通知できる
- 人件費を自動で計算できる
- 全13店舗をひとつのシステムで管理できる

### 1-2. アクセス方法

本番のURL: https://gyuumaru-shift.gyuumaru.workers.dev

このURLをスマホのブラウザで開くだけです。
アプリのインストールは不要です。

ホーム画面に追加しておくと、アプリのように使えて便利です。
- iPhone: Safariでページを開く → 共有ボタン → 「ホーム画面に追加」
- Android: Chromeでページを開く → メニュー → 「ホーム画面に追加」

## 2. スタッフ向けの使い方

### 2-1. シフト希望を出す

ステップ1: アプリを開く
- ブラウザでURLにアクセスすると、店舗選択画面が表示されます
- 自分が働いている店舗のカードをタップします

ステップ2: スタッフモードを選ぶ
- 「スタッフ」をタップします

ステップ3: 自分の名前を選ぶ
- スタッフ一覧が表示されるので、自分の名前をタップします
- これでログイン完了です

ステップ4: 「シフト希望を出す」をタップ
- スタッフメニューから「シフト希望を出す」を選びます
- 来月のカレンダーが表示されます

ステップ5: 日付をタップして希望を入力
- カレンダーの日付をタップすると、入力画面が出てきます
- 以下の3種類から選びます

| 選択肢 | 意味 | カレンダーの色 |
|--------|------|---------------|
| 出勤希望 | その日は働きたい | 緑 |
| 休み希望 | その日は休みたい | 赤 |
| どちらでも | どちらでも構わない | 黄 |

- 「出勤希望」と「どちらでも」の場合は、開始時間と終了時間も設定できます
  例: 18:00〜22:00 で出勤したい
- 「備考」欄にメモも書けます
  例: 「テスト期間なので早めに上がりたい」

ステップ6: 一括設定（便利な機能）
- 「一括設定」ボタンを使うと、複数の日にまとめて同じ希望をセットできます
- 例: 「毎週月・水・金は18:00〜22:00で出勤希望」と一度に設定

ステップ7: 提出する
- すべての日の希望を入力したら「提出する」ボタンをタップ
- 確認メッセージが出るので「OK」をタップすれば完了です
- 締切日（毎月20日が初期設定）までに提出してください

注意点:
- 希望を出し直したいときは、もう一度同じ手順で入力し直せます
  前回の希望が上書きされます
- 締切を過ぎると提出できなくなります
- 何も入力していない日は「どちらでも」と同じ扱いになります


### 2-2. 提出済みの希望を確認する

1. スタッフメニューから「提出済み希望を見る」をタップ
2. カレンダー形式で、自分が出した希望が色付きで表示されます
3. 月を切り替えて過去の希望も確認できます


### 2-3. 確定シフトを確認する

1. スタッフメニューから「確定シフトを見る」をタップ
2. 来月の確定シフトがカレンダーで表示されます
3. 各日付に出勤時間が表示されます
4. 「リスト表示」に切り替えると、表形式で詳しく見られます

| 表示項目 | 内容 |
|----------|------|
| 日付 | 2026-04-15 |
| 曜日 | 火 |
| 開始 | 11:00 |
| 終了 | 17:00 |
| 実働 | 5.25h |

5. 画面の上部に月間の合計情報も表示されます
   - 出勤日数: 何日出勤か
   - 月間労働時間: トータル何時間か

## 3. 管理者（店長）向けの使い方

### 3-1. 管理者としてログインする

ステップ1: アプリを開く
- 店舗選択画面で自分の店舗を選びます

ステップ2: 管理者モードを選ぶ
- 「管理者」をタップします

ステップ3: パスワードを入力する
- 管理者パスワードを入力して「ログイン」をタップします

初回ログインの場合:
パスワードがまだ設定されていないときは、
入力したパスワードがそのまま新しいパスワードとして登録されます。
忘れないように控えておいてください。


### 3-2. ダッシュボードの見方

ログインすると、ダッシュボード（管理画面のトップ）が表示されます。
ここでは以下の情報が一目でわかります。

- シフト希望の提出状況
  - プログレスバー（進捗バー）で「提出済み / 全スタッフ数」を表示
  - 未提出のスタッフの名前を一覧で表示
  - 例: 「12 / 20人が提出済み」

- 4つのメニューボタン
  - シフト希望一覧
  - シフト表作成・編集
  - 人件費確認
  - スタッフ管理


### 3-3. シフト希望一覧を確認する

ダッシュボードから「シフト希望一覧」をタップすると、
全スタッフのシフト希望をまとめて見ることができます。

- カレンダー表示: 日付ごとに出勤希望・休み希望・どちらでもの人数がわかる
- テーブル表示: スタッフごとの希望を一覧で確認できる


### 3-4. シフト表を作る（自動作成）

これがこのシステムの一番の目玉機能です。

ステップ1: ダッシュボードから「シフト表作成・編集」をタップ

ステップ2: 「自動作成」ボタンをタップ
- 確認メッセージが表示されるので「OK」をタップ
- システムが自動でシフト表を作ります（数秒で完了）

自動作成の仕組み:
1. 「出勤希望」を出しているスタッフをまず配置
2. ポジション（ホール/キッチン）ごとに必要人数をチェック
3. 足りなければ「どちらでも」の人から補充
4. 連勤6日以内、休息11時間以上、週40時間以内の制約をチェック

人数が足りない日がある場合:
- 警告メッセージが表示されます
  例: 「4/15(土) ホール: 必要5人に対して4人しか確保できません」
- この場合は手動で調整が必要です

ステップ3: シフト表を確認する
- マトリックス表示（スタッフ名が縦、日付が横）でシフト表が表示されます
- ポジションごとにグループ分けされています
  - ホール（正社員）
  - ホール（アルバイト）
  - キッチン（正社員）
  - キッチン（アルバイト）

表示の見方:

| 表示 | 意味 |
|------|------|
| 11-17 | 11:00〜17:00のシフトが入っている |
| 青い点線の枠 | 出勤希望が出ている日 |
| ピンクの点線の枠 | 休み希望が出ている日 |
| 黄色の点線の枠 | どちらでもが出ている日 |
| 空白 | シフトなし |

正社員の月間労働時間:
- 各正社員の行の右端にプログレスバーが表示されます
- 60時間を超えると注意（残業手当が発生）
- 80時間を超えると危険ライン（過労の恐れ）

出勤人数のサマリー:
- テーブルの下の行に、その日の出勤人数の合計が表示されます
- 平日の最低人数（ホール3/キッチン2）、土日の最低人数（ホール5/キッチン4）を
  下回っている日は赤く表示されます


### 3-5. シフトを手動で調整する

自動作成の結果を手動で修正したい場合は、以下の操作ができます。

シフトを追加:
1. 空いているセル（スタッフx日付の交差点）をタップ
2. 「追加」をタップ
3. 開始時間と終了時間を選んで「保存」

シフトを変更:
1. すでにシフトが入っているセルをタップ
2. 「編集」をタップ
3. 時間を変更して「保存」

シフトを削除:
1. シフトが入っているセルをタップ
2. 「削除」をタップ
3. 確認メッセージで「OK」


### 3-6. シフトを確定する

シフト表の調整が終わったら、シフトを確定します。

1. 「シフト確定」ボタンをタップ
2. 確認メッセージで「OK」をタップ
3. ステータスが「仮」から「確定」に変わります

注意:
- シフトが0件の状態で確定しようとすると警告が出ます
- 確定後もシフトの追加・変更・削除は可能です
  （ステータスが「変更あり」に変わります）


### 3-7. LINEで通知する

シフトを確定したら、スタッフにLINEで通知できます。

1. 「LINE通知」ボタンをタップ
2. 確認メッセージで「OK」をタップ
3. 店舗のLINE公式アカウントから通知が送信されます

通知の内容:
```
【嬉野本店】
4月のシフトが確定しました!
システムにログインして確認してください。
```

注意:
- LINE通知を使うには、事前にLINE Messaging APIの設定が必要です
- LINE_CHANNEL_TOKEN が設定されていない場合は通知できません

リマインド通知:
- 「リマインド通知」ボタンで、まだ希望を出していないスタッフに催促できます
- 未提出者の名前も通知に含まれます


### 3-8. スタッフを管理する

ダッシュボードから「スタッフ管理」をタップします。

新しいスタッフを登録する:
1. 「スタッフ追加」ボタンをタップ
2. 必要な情報を入力する

| 入力項目 | 入力内容 | 必須か |
|----------|---------|--------|
| 氏名 | スタッフの名前 | 必須 |
| フリガナ | カタカナで名前 | 任意 |
| 雇用区分 | 正社員/アルバイト/パート | 必須 |
| ポジション | ホール/キッチン | 必須 |
| 時給 | アルバイト・パートの時給 | 雇用区分による |
| 月給 | 正社員の月給 | 雇用区分による |
| 交通費（日額） | 1日の交通費 | 任意 |
| 電話番号 | 連絡先 | 任意 |
| メール | メールアドレス | 任意 |
| 週上限時間 | 週何時間まで働けるか | 初期値40 |
| 固定休み | 毎週決まった休みの日 | 任意 |

3. 「保存」をタップ

スタッフの情報を変更する:
1. スタッフ一覧でそのスタッフの「編集」をタップ
2. 情報を修正して「保存」

スタッフを退職扱いにする:
1. スタッフ一覧でそのスタッフの「退職」をタップ
2. 確認メッセージで「OK」
3. ステータスが「退職」になり、シフト希望画面に表示されなくなります
4. データ自体は残るので、過去のシフトや人件費は引き続き確認できます


### 3-9. 人件費を確認する

ダッシュボードから「人件費確認」をタップします。

1. 対象月を選ぶ（初期値は来月）
2. 「計算実行」ボタンをタップ
3. スタッフ別の人件費テーブルが表示されます

| 表示項目 | 内容 |
|----------|------|
| スタッフ名 | 田中太郎 |
| 雇用区分 | アルバイト |
| 労働時間 | 120.5h |
| 基本給 | 120,500円 |
| 深夜手当 | 3,750円 |
| 残業手当 | 1,250円 |
| 交通費 | 8,000円 |
| 合計 | 133,500円 |

テーブルの最下段に、全スタッフの合計も表示されます。

計算の仕組み:

基本給:
- 正社員 → 月給がそのまま
- アルバイト・パート → 時給 x 実働時間

深夜手当（22:00〜翌5:00の分、アルバイト・パートのみ）:
- 時給 x 深夜時間 x 0.25

残業手当:
- 正社員: 月60時間超で 月給/160 x 超過時間 x 1.3
- アルバイト: 週40時間超で 時給 x 超過時間 x 0.25

交通費:
- 1日あたりの交通費 x 出勤日数

休憩時間は自動控除:
- 6時間超: 45分
- 8時間超: 60分

## 4. 毎月のシフト運用フロー

毎月決まった手順でシフトを回していくと、スムーズに運用できます。

### 4-1. 月のスケジュール

| 時期 | やること | 誰が |
|------|---------|------|
| 1日〜20日 | 来月のシフト希望を提出 | スタッフ全員 |
| 15日頃 | 未提出者にリマインド通知 | 店長 |
| 20日（締切） | 希望の提出を締め切る | 自動 |
| 21日〜25日 | シフト表を作成・調整する | 店長 |
| 25日頃 | シフトを確定してLINE通知 | 店長 |
| 翌月1日〜 | 確定シフトに従って勤務 | スタッフ全員 |
| 月末 | 人件費を計算・確認 | 店長 |

### 4-2. 具体的な手順

例: 4月分のシフトを作る場合

3月1日〜20日: スタッフが希望を出す
- スタッフはスマホからアプリを開いて4月の希望を提出
- 店舗のLINEグループにURLを固定メッセージで貼っておくと便利

3月15日頃: リマインド通知
- 店長がダッシュボードで提出状況を確認
- 未提出者がいたら「リマインド通知」をタップしてLINEで催促
- または直接声をかける

3月20日: 締切
- この日を過ぎるとスタッフは希望を出せなくなる
- 締切日は店舗設定で変更可能（初期値は20日）

3月21日〜25日: シフト作成
1. 店長が「シフト表作成・編集」画面を開く
2. 「自動作成」をタップ
3. 人員不足の警告を確認
4. 足りない日は手動で調整（スタッフに直接相談して追加）
5. 全体のバランスを見て微調整

3月25日頃: シフト確定・通知
1. 「シフト確定」をタップ
2. 「LINE通知」をタップしてスタッフに知らせる
3. スタッフは確定シフトをアプリで確認

4月末: 人件費計算
1. 「人件費確認」画面で4月分を計算
2. スタッフ別の人件費を確認
3. 必要に応じて経理に共有

## 5. よくある操作シーン

### 5-1. スタッフが急に休むことになった

1. 店長が「シフト表作成・編集」画面を開く
2. 休むスタッフのその日のシフトをタップ
3. 「削除」をタップしてシフトを消す
4. 代わりに出られるスタッフがいたら、空いたセルをタップして「追加」
5. 必要に応じてLINEでスタッフに連絡


### 5-2. 新しいスタッフが入った

1. 店長が「スタッフ管理」画面を開く
2. 「スタッフ追加」をタップ
3. 氏名、ポジション（ホール/キッチン）、雇用区分、時給などを入力
4. 「保存」をタップ
5. 翌月の希望を出せるよう、新スタッフにアプリのURLを伝える


### 5-3. スタッフが退職した

1. 店長が「スタッフ管理」画面を開く
2. 退職するスタッフの「退職」をタップ
3. そのスタッフはスタッフ選択画面に表示されなくなる
4. 過去のシフトや人件費データは残る


### 5-4. 管理者パスワードを変更したい

1. 管理者としてログインした状態で、パスワード変更のAPIを使う
   （現時点では画面上のボタンはないため、開発者に依頼してください）


### 5-5. 希望の締切日を変更したい

各店舗の設定で「希望締切日」を変更できます。
（現時点ではデータベースの直接変更が必要なため、開発者に依頼してください）

## 6. 便利な使い方のコツ

### 6-1. スタッフ向けのコツ

- ホーム画面に追加しておく
  毎月URLを探す手間がなくなります

- 一括設定を活用する
  「毎週月水金は夜シフト」のようにまとめて設定すると、1日ずつ入力する手間が省けます

- 備考欄を活用する
  「この日は18時以降なら出られます」のように書いておくと、
  店長がシフトを組むときの参考になります

- 早めに提出する
  締切ギリギリだと修正できません。余裕を持って提出しましょう

### 6-2. 管理者向けのコツ

- リマインド通知は締切の3〜5日前に送る
  早すぎると効果が薄く、遅すぎると間に合わないので、
  15日〜17日頃がおすすめです

- 自動作成の結果は必ず確認する
  自動作成はあくまでベースです。特に土日の人数が足りているか、
  正社員の月間労働時間が60時間を大きく超えていないかをチェックしましょう

- 人件費は月末にこまめにチェック
  残業が膨らんでいるスタッフがいないか、月末に確認しましょう

- LINEグループにURLを固定メッセージで貼る
  スタッフが迷わずアクセスできます

- シフト表を確定したらすぐLINE通知
  確定とLINE通知はセットで行いましょう

## 7. 困ったときは

### 7-1. ログインできない

- パスワードが間違っていないか確認してください
- 初回ログイン時は、入力したパスワードがそのまま登録されます
- どうしてもわからない場合は、開発者にパスワードリセットを依頼してください

### 7-2. シフト希望が提出できない

- 締切日（初期設定は毎月20日）を過ぎていないか確認してください
- 締切後は提出できません

### 7-3. 自動作成で警告が出る

- 「必要人数に対して足りない」という警告は正常な動作です
- スタッフの希望数がそもそも足りない日は、どうしても不足します
- 手動で調整するか、スタッフに直接相談して追加してもらいましょう

### 7-4. 画面が真っ白になった

- ブラウザのキャッシュをクリアしてみてください
- ページを再読み込みしてみてください
- それでも解決しない場合は、別のブラウザで試してみてください

### 7-5. LINE通知が届かない

- LINE_CHANNEL_TOKEN が正しく設定されているか確認してください
- LINE公式アカウントがグループに参加しているか確認してください
- 「テスト通知」ボタンでまず試してみてください

## 8. 店舗への初期導入手順

新しい店舗にこのシステムを導入する場合の手順です。
（この作業は開発者またはシステム担当者が行います）

### 8-1. 必要な準備

- パソコン（初期設定時のみ、日々の利用はスマホでOK）
- Cloudflareアカウント
- Node.jsとnpmがインストール済みであること
- LINE公式アカウント（LINE通知を使う場合）

### 8-2. 初期セットアップの流れ

1. データベースに店舗データがあることを確認
   13店舗分のデータはすでにseed.sqlで投入済みです

2. 管理者パスワードを設定
   初めてその店舗の管理者としてログインしたとき、
   入力したパスワードがそのまま登録されます

3. スタッフを登録
   管理者画面の「スタッフ管理」から、その店舗のスタッフを登録します

4. 店舗設定を確認
   営業時間、最低人数、希望締切日などのデフォルト設定が合っているか確認します
   変更が必要な場合はデータベースの store_settings テーブルを直接更新します

5. LINEを設定（任意）
   LINE Developers でチャネルトークンを発行し、
   store_settings テーブルの LINE_CHANNEL_TOKEN に設定します

6. スタッフにURLを共有
   店舗のLINEグループにURLを投稿して、スタッフにアクセス方法を伝えます

### 8-3. 店舗設定の変更方法

現時点では、店舗ごとの設定変更はデータベースの直接更新が必要です。

変更可能な設定:

| 設定項目 | 初期値 | 説明 |
|----------|--------|------|
| 営業開始時間 | 11:00 | 何時に開店するか |
| 営業終了時間 | 22:00 | 何時に閉店するか |
| 平日ホール最低人数 | 3 | 平日のホール最低人数 |
| 平日キッチン最低人数 | 2 | 平日のキッチン最低人数 |
| 土日ホール最低人数 | 5 | 土日のホール最低人数 |
| 土日キッチン最低人数 | 4 | 土日のキッチン最低人数 |
| 希望締切日 | 20 | 毎月何日に希望を締め切るか |
| 正社員月間上限時間 | 60 | 正社員の月間残業なし上限 |

## 9. データのバックアップについて

### 9-1. データの保存先

すべてのデータはCloudflare D1に保存されています。
Cloudflareのインフラは冗長化されているため、
通常のサーバー障害でデータが消えることはありません。

### 9-2. ソースコードのバックアップ

ソースコードはGitHubで管理されています。
リポジトリ: https://github.com/soutatakeezwjp-wq/gyuumaru-shift
（非公開リポジトリ）

### 9-3. データのエクスポート

現時点では、データの手動エクスポート機能はありません。
必要に応じてAPIを使ってデータを取得し、CSV等に変換することは可能です。

## 10. セキュリティに関する注意事項

### 10-1. 管理者パスワードについて

- 管理者パスワードは各店舗の店長だけが知っている状態にしてください
- パスワードは暗号化（SHA-256ハッシュ）されて保存されるので、
  データベースを見ても元のパスワードはわかりません
- 簡単なパスワード（1234、password等）は避けてください

### 10-2. URLの共有について

- スタッフ用のURL（通常のURL）はスタッフに共有してOKです
- 管理者としてログインするにはパスワードが必要なので、
  URLを知っているだけでは管理画面には入れません

### 10-3. ログイン状態について

- ログインの有効期限は24時間です
- 24時間経つと自動的にログアウトされます
- セキュリティが気になる場合は、使い終わったらブラウザのタブを閉じてください

### 10-4. 個人情報の取り扱い

- スタッフの個人情報（電話番号、メール等）はデータベースに保存されます
- 店舗間でデータが混ざることはありません（マルチテナント分離）
- GitHubにアップロードされるコードには個人情報は含まれません

## 11. システムの費用について

### 11-1. 現在のプラン

Cloudflare Workers の無料プラン（Free Plan）で運用しています。

| 項目 | 無料枠 | 参考: 13店舗で使った場合の目安 |
|------|--------|-------------------------------|
| リクエスト数 | 1日10万回まで | 1日1,000回程度 |
| D1読み取り | 月500万回まで | 月数万回程度 |
| D1書き込み | 月10万回まで | 月数千回程度 |
| D1データ容量 | 5GBまで | 数十MB程度 |

13店舗のシフト管理であれば、無料枠で十分に余裕があります。

### 11-2. 有料プランへの移行が必要になる場合

- 店舗数が大幅に増えた場合（50店舗以上など）
- 同時アクセスが極端に多い場合
- データ量が5GBを超えた場合

この場合は、Cloudflare Workers Paid Plan（月$5〜）への移行が必要です。
